01

WITA zone aggregation

Translate detailed SATURN origin-destination data into WITA analysis zones. Sum demand and calculate demand-weighted distance and time values across scenarios, years, time periods, and user classes.

ZONE CORRESPONDENCE   /   WEIGHTED MEANS   /   MATRIX INDEXING
Inside the workflow

The Excel lookup maps transport model origins and destinations to WITA zones. Grouped sums aggregate demand; weighted sums calculate the generalised-cost inputs that WITA needs. Reindexing creates every target OD combination, with zero-filled missing combinations. The configured run covers 2037 and 2052, DM/DS1/DS2, four time periods, and user classes 1–9.

02

Highway demand averaging

Pair Do Minimum demand with each Do Something scenario, validate the origin-destination rows, and produce averaged demand files while preserving distance and time inputs.

BATCH PROCESSING   /   OD VALIDATION   /   SCENARIO PAIRING
Inside the workflow

Each DM file must have corresponding DS1 and DS2 files. Row counts and the first two columns must match in the same order before averaging the third column. Each pair produces (DM + DS) / 2; this is scenario averaging, not averaging across years.

Shared WITA/TUBA scheme files

Generate a family of scheme files in the shared TUBA/WITA format, combining highway variants, rail variants, and user-class selections with consistent matrix references.

TEMPLATE PROCESSING   /   CONFIGURATION MAPPINGS   /   TEXT FORMATTING
Inside the workflow

WITA runs alongside TUBA and reuses the scheme-file structure, economics inputs, and matrices. Four highway variants, two rail variants, and two highway user-class sets define 16 configured combinations. The generator builds USER_CLASSES and INPUT_MATRICES sections while preserving the template header and SECTORS footer.

Engineering approach

Prepare inputs that WITA can inspect.

WITA estimates wider impacts alongside conventional user benefits. These workflows prepare the zone-level demand, cost, and shared scheme-file inputs that connect transport-model outputs to that appraisal.

The scripts pass Python syntax checks. Full end-to-end execution needs the original matrix inputs, lookup, and scheme template, which are not included. The README documents current limitations and separates this workflow's demand averaging from WITA's own cost-averaging methods.
